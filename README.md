# Hallmark — Image Processing & AI Automation

Implements the **Technical Report: Image Processing & AI Automation Challenge**
for the jewelry hallmarking & inventory system: a dual-track pipeline that turns
**one product photo + a UID + a weight** into the standardised **3-pane
compliance composite** the government portal requires for every item.

```
┌──────────────┬──────────────┬──────────────┐
│  UID IMAGE   │ MODEL IMAGE  │ WEIGHT IMAGE │
│ etched UID   │ studio shot  │ item + scale │
└──────────────┴──────────────┴──────────────┘
```

Replaces the ~2 min/item of manual photography (≈6.5 hrs for a 200-item batch)
with a sub-minute programmatic step.

> **Looking for the website?** A single-admin **PHP MVC** web app built on the
> same engine (ported to PHP GD) lives in [`hallmark-web/`](hallmark-web/) —
> login, dashboard, upload form and stored item history. This Python package is
> the standalone image-engine / API reference.

## The two tracks (report §3)

| | Track A — AI Automation (preferred) | Track B — Template Overlay (fallback) |
|---|---|---|
| Inputs | 1 model photo + UID & weight text | model photo + UID close-up + weight text |
| UID pane | deterministic metal-plate render of the real UID | your uploaded UID macro |
| Model pane | provider-enhanced studio shot | uploaded photo |
| Weight pane | rendered scale showing the measured weight | same |
| Per-image cost | 0 INR default (paid model optional, capped < 1 INR) | 0 INR |

The track is chosen automatically: **supply a `uid_image` → Track B**, omit it → Track A.

## Cost model — why it stays under ₹1/image

The report requires **< 1 INR per image**. Two of the three panes are **never**
generated by an AI model:

- **UID** and **Weight** are *facts* (an etched string, a measured number).
  Generative models render exact text/digits unreliably, and a hallucinated
  value would fail compliance — so both are drawn **deterministically with
  Pillow at ₹0**.
- Only the **model/product pane** can benefit from generation, and it's behind
  a pluggable provider:

| Provider | Per-image | Notes |
|---|---|---|
| `passthrough` *(default)* | **₹0** | uploaded photo, auto-contrast; no dependency |
| `rembg` | **₹0** | local background removal (`pip install rembg onnxruntime`) |
| `flux` | **~₹0.25** | hosted FLUX.1 [schnell]; needs `FAL_KEY`/`REPLICATE_API_TOKEN` |

A per-image **cost ceiling** (`HALLMARK_MAX_COST_INR`, default `1.0`) is enforced
in code — any provider over the cap silently falls back to the free path, so a
request never exceeds the budget or fails because the paid tier is offline.
API costs, when incurred, are flagged as **billable to the client** (report §4).

## Quick start

```bash
pip install -r requirements.txt

# Run the API + upload UI
uvicorn app.main:app --reload
# open http://127.0.0.1:8000/

# Or generate a demo composite with no server
python scripts/generate_sample.py            # -> samples/demo_composite.png
```

## API

`POST /api/composite` (multipart form)

| field | type | required | notes |
|---|---|---|---|
| `uid` | text | ✓ | laser-etched UID string |
| `weight_grams` | number | ✓ | measured weight |
| `item_type` | text | | e.g. Ring, Pendant, Stud |
| `company` | text | | shown in the header |
| `model_image` | file | ✓ | single studio product photo |
| `uid_image` | file | | UID macro → switches to Track B |
| `provider` | query | | override model-pane provider |

Returns a `image/png` composite. Response headers report the outcome:
`X-Compliance-Track`, `X-Model-Provider`, `X-Cost-INR`, `X-Billed-To-Client`.

`GET /api/config` — active provider, cost ceiling, billing flag.
`GET /health` — liveness.

## Configuration (env vars)

| var | default | purpose |
|---|---|---|
| `HALLMARK_AI_PROVIDER` | `passthrough` | `passthrough` \| `rembg` \| `flux` |
| `HALLMARK_MAX_COST_INR` | `1.0` | per-image cost ceiling |
| `HALLMARK_BILL_CLIENT` | `true` | bill API cost to the client |
| `HALLMARK_OUTPUT_DIR` | `output` | where composites are saved (empty = don't save) |
| `FAL_KEY` / `REPLICATE_API_TOKEN` | — | required only for `flux` |

## Layout

```
app/
  main.py                 FastAPI app + UI mount
  config.py               env-driven settings & cost ceiling
  routers/compliance.py   /api/composite, /api/config
  services/
    compositor.py         Track B engine — the 3-pane builder (core)
    ai_generator.py       Track A — pluggable model-pane provider
    image_utils.py        Pillow helpers (fonts, fit, panels)
  static/index.html       upload UI
scripts/generate_sample.py
tests/                    pytest suite (engine + API)
```

Run the tests with `python -m pytest`.

## Scope note

This module covers the **second PDF** (image processing & automation) only.
The broader system items from the meeting summary (multi-tenant admin, receipts,
OTP, vendor profiles) are intentionally out of scope here.
